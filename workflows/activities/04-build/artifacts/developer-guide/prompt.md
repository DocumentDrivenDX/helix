# Developer Guide authoring prompt

Help an unfamiliar developer run the project, locate a change, and verify it.
Read the project's contributor instructions, build definitions, tests, and
installation guidance before writing commands. State working directory,
prerequisites, supported environment evidence, expected results, and recovery
steps. Separate local deterministic checks from live integrations and deployment.
Map canonical sources to generated outputs and regeneration commands. Provide a
small realistic first contribution plus common change recipes tied to checks.
Link to the solution overview, architecture walkthroughs, and operational runbooks.
Keep architectural decisions in Architecture/ADRs and incident response in runbooks.
Do not claim onboarding is proven from a repository read or passing static tests.
Record a newcomer trial in the project's verification evidence or tracker, not
in the guide: environment, task, observed result, help needed, and remaining
blockers. The guide states only what a reader acts on.
Name the maintainer role and update triggers. Verify paths and commands.
